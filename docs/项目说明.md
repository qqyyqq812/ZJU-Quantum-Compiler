# 项目说明

本文说明 ZJU Quantum Compiler 的项目目标、算法流程、接口使用方式、目录结构
和结果边界。读者可以先通过本文了解项目整体，再根据 README 运行代码或查看
网页演示。

## 项目概述

ZJU Quantum Compiler 是一个神经辅助量子路由编译器。项目处理的问题是：理想
量子电路通常默认任意两个逻辑量子比特都能直接执行双比特门，但真实量子芯片
只有固定的物理连接。编译器需要把逻辑量子比特放到物理量子比特上，并在必要
位置插入 SWAP 门，让电路能够在目标芯片拓扑上合法执行。

项目默认使用 NPQR 编译流程。NPQR 的核心是神经网络推理，但完整路由结果还依赖
初始映射选择、束搜索、动作剪枝、局部后缀修复和轨迹校验。SABRE 是对比基线，
用于展示经典启发式路由算法的效果。

## 问题定义

输入包括两部分：

- OpenQASM 2 格式的量子电路。
- 目标硬件拓扑，当前默认使用 IBM Tokyo 20Q 连接图。

输出包括：

- 路由后的 OpenQASM 电路。
- 插入的 SWAP 数。
- 路由后电路深度。
- 编译耗时。
- 可复放的路由轨迹。
- SABRE 基线结果。

优化目标是在保证拓扑合法和电路语义一致的前提下，尽量减少 SWAP 数和电路深度，
同时把运行时间控制在可演示和可调用的范围内。

## 算法流程

NPQR 可以理解为“神经网络评分 + 经典搜索控制”的组合式算法。流程如下：

1. 解析输入电路。
   系统读取 OpenQASM 2 文本，提取量子门序列，并记录双比特门之间的依赖关系。

2. 建立硬件图。
   目标芯片被表示为无向图。物理量子比特是顶点，硬件连接是边。系统会预先计算
   物理量子比特之间的距离，用于后续评分。

3. 选择初始映射。
   系统根据电路中的量子比特交互关系和芯片拓扑生成多个逻辑到物理的映射候选。
   好的初始映射可以减少后续 SWAP。

4. 识别前沿门。
   当前没有未满足依赖的双比特门被称为前沿门。若前沿门对应的两个物理量子比特
   已经相邻，就可以直接执行；否则需要插入 SWAP。

5. 神经网络评估动作。
   模型根据当前映射、前沿门和候选 SWAP 动作进行推理，给合法动作分配偏好分数。
   这里的神经网络不是单独输出完整电路，而是在搜索过程中提供动作判断。

6. 束搜索展开路线。
   系统不会只保留单条路线，而是保留若干条候选路线继续展开。这样可以降低局部
   贪心选择导致失败的风险。

7. 触发规则和动作剪枝。
   对交互更密集、普通路线容易卡住的电路，系统会启用更强的前沿搜索；同时通过
   剪枝减少明显较差的候选动作，控制搜索规模。

8. 局部后缀修复。
   当路线已经完成大部分门、但最后少量门卡住时，系统会进行有界局部搜索，尝试
   修复剩余后缀。

9. 轨迹复放验证。
   系统重新模拟输出轨迹，检查每一步门和 SWAP 是否满足芯片连接约束。只有通过
   复放验证的路线才会作为 NPQR 结果返回。

## 与 SABRE 的关系

SABRE 是 Qiskit 中常用的量子路由启发式算法。它根据当前前沿门和后续门的距离
估计来选择 SWAP，稳定性较好，适合作为基线。

本项目中的 SABRE 只用于对比。NPQR 的结果不依赖 SABRE 兜底完成。接口返回中会
同时给出 NPQR 和 SABRE 的关键指标，便于观察两种路线在不同电路上的差异。

## 课程算法概念

项目可以对应到多种课程算法思想：

| 课程概念 | 项目中的对应关系 |
| --- | --- |
| 图问题 | 芯片拓扑是图，路由过程受图边约束。 |
| 变治法 | 把量子路由转化为拓扑图上的映射和搜索问题。 |
| 贪婪思想 | 前沿门距离可以作为局部动作质量的参考。 |
| 减治法 | 每执行一个合法门，剩余待执行门数量减少。 |
| 时空权衡 | 距离矩阵、候选映射和候选路线占用空间，但减少重复计算。 |
| 迭代改进 | 路线通过连续 SWAP、映射更新和修复逐步改进。 |
| 搜索剪枝 | 束宽、触发规则和动作剪枝控制搜索树规模。 |
| 近似求解 | 系统追求有限时间内的高质量可行解，不保证全局最优。 |
| 神经网络 | 模型在搜索循环中提供动作偏好。 |

## 接口说明

项目提供 REST API、MCP 服务和命令行三种使用方式。

### REST API

REST API 适合网页和普通后端调用。启动命令如下：

```bash
uvicorn src.server.app:app --host 0.0.0.0 --port 8765
```

常用接口如下：

| 接口 | 作用 |
| --- | --- |
| `GET /api/status` | 查看后端、模型和默认编译器状态。 |
| `GET /api/examples` | 获取内置 QASM 示例。 |
| `POST /api/compile` | 编译示例电路或自定义 QASM。 |
| `GET /api/benchmarks` | 查看算法边界和固定示例摘要。 |
| `GET /api/npqr/evidence` | 获取机器可读算法说明。 |

### MCP 服务

MCP 服务适合工具客户端调用。启动命令如下：

```bash
qcompiler-mcp-http
```

默认地址为：

```text
http://127.0.0.1:8000/mcp
```

主要工具包括 `compile_npqr`、`compile_sabre`、`compile_qasm`、
`list_examples` 和 `get_algorithm_evidence`。

### 命令行

命令行适合快速检查和本地演示：

```bash
qcompiler info
qcompiler compile --example qft5 --backend npqr
qcompiler matrix --quick
```

## 结果边界

NPQR 是一个可运行的神经辅助量子路由流程。它可以通过 REST API、MCP 和命令行
调用，并能返回可复放的路由轨迹。

项目不声明 NPQR 在所有电路上都优于 SABRE，也不声明默认模型是最先进的量子
路由模型。当前更适合客观表述为：项目实现了一个结合神经网络推理和经典搜索的
量子路由编译流程，并提供了可运行、可展示、可解释的工程接口。
