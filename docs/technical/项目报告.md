## 2. 量子路由的物理机制

量子算法通常写在逻辑比特集合上，默认任意两个逻辑比特都可以执行双比特
门。但真实 NISQ 芯片有固定耦合拓扑，物理比特之间只有部分边可以直接
执行 CX/CNOT。以 IBM Tokyo 20Q 为例，硬件可以抽象成图：

- 节点表示物理量子比特。
- 边表示允许执行双比特门的物理连接。
- 逻辑比特到物理比特的映射会随 SWAP 操作变化。

当一个逻辑 CX 门作用在逻辑比特 `(q_i, q_j)` 上时，当前映射
`pi(q_i), pi(q_j)` 必须对应硬件图中的相邻物理节点。若二者不相邻，
编译器需要插入 SWAP 门移动量子态。一个 SWAP 通常可以分解为 3 个 CX，
所以 SWAP 数会直接增加 CNOT 总数、深度和噪声暴露时间。

因此，本项目优化的核心指标是：

- 路由后 SWAP 数。
- 路由后 CX/CNOT 或双比特门总数。
- 路由后电路深度。
- 路由完成率。
- 与 Qiskit SABRE 在同一拓扑、同一电路集合上的对比。

这个问题本质上是 NP-hard 的组合优化：每一步 SWAP 都改变后续门的可执行性，
局部最短路径选择不一定带来全局最优路由。

## 3. DAG 表示与前沿门执行

`src/compiler/dag.py` 将 Qiskit `QuantumCircuit` 转换为电路 DAG：

- DAG 节点是量子门。
- DAG 边表示同一逻辑比特上的先后依赖。
- `get_front_layer()` 返回所有前驱已经执行的门。
- `execute_executable()` 自动执行当前映射下满足拓扑约束的前沿门。
- `apply_swap()` 更新逻辑到物理比特的映射。

这个设计让路由器只在必要时选择 SWAP。单比特门无拓扑约束，可以直接执行；
双比特门只有在映射后的物理比特相邻时才能执行。前沿门和 look-ahead 门
共同构成路由决策的局部物理图像。

## 4. MDP 建模

`src/compiler/env.py` 将量子路由写成 Gymnasium 风格 MDP：

| MDP 组件 | 本项目实现 |
| --- | --- |
| 状态 | 当前逻辑-物理映射、前沿门距离、扩展前沿距离、剩余门统计、拓扑图特征 |
| 动作 | 每条物理边上的 `SWAP(p_i, p_j)`，外加 `PASS` 动作 |
| 转移 | SWAP 更新映射；PASS 或 SWAP 后尝试执行所有可执行前沿门 |
| 奖励 | 执行门奖励、SWAP 惩罚、距离缩短 shaping、完成奖励、SABRE 相对奖励 |
| 终止 | 所有 DAG 门执行完毕，或达到 `max_steps` |

动作 mask 是关键工程点。早期版本若允许所有 SWAP，策略会在无意义动作中
浪费大量采样。V14 根据课程阶段使用 hard/soft mask：简单阶段只允许能
缩短前沿或扩展前沿距离的 SWAP，后期再逐步放宽，避免模型完全被手写规则
锁死。

## 5. 算法设计大作业对应分析

`docs/算法设计与智能计算大作业-2026.pdf` 第一部分要求完成算法设计、
性能与复杂度分析、代码实现和课堂展示。本项目可以作为该部分的主载体，
但叙事重点必须放在算法问题本身，而不是只展示工程页面。

推荐题目为：

> 面向 NISQ 量子芯片拓扑约束的量子电路路由算法设计与智能优化

### 5.1 形式化问题定义

给定逻辑电路 DAG `D=(Gates, Dep)`、物理耦合图 `H=(P,E)`、逻辑比特集合
`Q` 和当前映射 `pi: Q -> P`，每一步路由决策需要选择：

- 执行当前映射下已经满足拓扑约束的前沿门。
- 或在物理边 `(p_i,p_j) in E` 上插入 `SWAP(p_i,p_j)`，并更新 `pi`。
- 或在受控场景下执行 `PASS`，让环境尝试推进所有可执行门。

目标函数可以写成多目标优化：

```text
minimize  alpha * #SWAP + beta * depth + gamma * #CX
subject to every two-qubit gate is executed on adjacent physical qubits
```

其中 `#SWAP` 是最直接指标，`depth` 和 `#CX` 体现硬件噪声风险。由于任意
一次 SWAP 都会改变后续所有门的物理位置，这个问题不是简单最短路，而是
带状态依赖的组合搜索问题。

### 5.2 核心算法流程

本项目的 AI 路由器可以概括为下面的算法：

```text
Input: quantum circuit C, coupling graph H, initial mapping pi
Build DAG D from C
Execute all front-layer gates that are legal under pi
while D is not finished and step < max_steps:
    Build observation from pi, front layer, look-ahead layer, and H
    Build action mask from distance-improving SWAP candidates
    Select action a using policy network or MCTS
    if a is SWAP(p_i, p_j):
        Insert SWAP and update pi
    else:
        Try PASS execution
    Execute all newly legal front-layer gates
    Accumulate reward and trace
return routed circuit, #SWAP, completion status
```

这段流程对应的源码入口是：

- `src/compiler/dag.py`：构造 DAG、维护 front layer、判断门是否可执行。
- `src/compiler/env.py`：定义 observation、action、reward、mask 和终止条件。
- `src/compiler/policy.py`：用 GraphSAGE + actor-critic 选择动作。
- `src/compiler/pass_manager.py`：把 AI trace 回写成真实 Qiskit 电路。

### 5.3 复杂度分析

设物理比特数为 `n=|P|`，物理边数为 `m=|E|`，电路门数为 `g`，前沿门数量为
`f`，look-ahead 门数量为 `l`，单次路由最多执行 `T` 个决策步。

| 算法环节 | 时间复杂度 | 说明 |
| --- | --- | --- |
| DAG 构建 | `O(g)` | 每个门生成一个节点，并加入同一逻辑比特上的依赖边 |
| 前沿门更新 | `O(f)` 到 `O(g)` | 实现上按前驱完成状态筛选，规模受电路宽度和依赖结构影响 |
| 候选 SWAP 枚举 | `O(m)` | 每条物理边是一个可选动作 |
| 动作 mask 评分 | `O(m(f+l))` | 对候选 SWAP 估计前沿和 look-ahead 距离变化 |
| GraphSAGE 前向 | 约 `O(L(m+n)d^2)` | `L` 为消息传递层数，`d` 为隐藏维度 |
| 单步 RL 推理 | `O(m(f+l) + L(m+n)d^2)` | mask、图编码和边打分共同构成单步成本 |
| 完整 AI 路由 | `O(T * single_step)` | `T` 由 `max_steps` 和电路难度决定 |
| MCTS 推理 | `O(S * single_step)` | `S` 为 simulations 数，当前 V15 仍需 batch 化优化 |

SABRE 的单步复杂度同样与候选 SWAP 数、front layer 和 look-ahead 集合有关。
它的优势在于启发式强、实现高效、无需训练；AI 路由器的优势是可以学习
跨电路和跨拓扑的策略先验，但当前 checkpoint 还没有把这种潜力转化为
超过 SABRE 的实测结果。

### 5.4 为什么当前 RL 没有超过 SABRE

失败诊断本身是本项目的重要算法结论：

- 奖励稀疏：只有接近完成时才能知道是否优于 SABRE。
- 动作空间大：IBM Tokyo 20Q 有 43 条物理边，即每步有几十个 SWAP 候选。
- mask 两难：hard mask 容易退化成局部贪心，soft mask 会显著降低采样效率。
- 课程断层：从“完成电路”切到“超过 SABRE”时，reward 分布变化过大。
- V15 瓶颈：MCTS 叶节点单状态推理、self-play 基本串行，吞吐不足。

因此，算法作业中更可信的结论不是“AI 获胜”，而是“实现了完整算法管线，
并用实验证明当前 RL/MCTS 路线的关键瓶颈在哪里”。

## 6. GNN/RL 路由器架构

AI 路由器由两个主要部分组成：

1. `QuantumRoutingEnv` 负责物理约束、DAG 执行和奖励。
2. `PolicyNetwork` 负责根据状态选择 SWAP 或 PASS。

`src/compiler/gnn_extractor.py` 将物理拓扑提取为图数据。每个物理比特节点
包含 9 维特征，包括节点度数、是否承载逻辑比特、是否参与前沿门、前沿
目标距离、剩余双比特门统计等。`src/compiler/gnn_encoder.py` 使用纯
PyTorch GraphSAGE 进行三层消息传递，不依赖 `torch_geometric`。

策略网络采用 actor-critic 结构：

- GraphSAGE 编码物理拓扑和当前映射状态。
- 扁平 observation 编码全局统计特征。
- Edge-scoring actor 对每条物理 SWAP 边独立打分。
- Value head 估计当前状态价值，用于 PPO 训练。

这种结构比固定动作 MLP 更适合拓扑变化，因为 SWAP 候选天然就是物理图的边。

## 7. 初始映射与 SWAP 插入

课题要求“动态决策初始映射和 SWAP 门插入策略”。本项目有两层实现：

- `src/compiler/initial_mapping.py` 提供基于逻辑交互图和物理距离矩阵的
  贪心初始映射。它优先把高频交互逻辑比特放到物理距离短的位置。
- RL/GNN 路由器在每个决策点选择 SWAP 或 PASS，动态更新映射并推进 DAG。

当前 P1 评测为了公平复现主要使用 identity mapping 路径，避免随机初始
映射干扰 AI/SABRE 对比。初始映射优化作为可用模块保留，但不是 P1 主结论
的来源。

## 8. Qiskit 插件与工程接口

项目通过 `pyproject.toml` 暴露 `qcompiler` 命令，同时在
`src/compiler/pass_manager.py` 中提供 `AIRouter`：

- `AIRouter.route()` 运行 AI 策略并构建带 SWAP 的 Qiskit `QuantumCircuit`。
- `AIRouter.route_count_only()` 用于公平评测 SWAP 数和完成状态。
- `compile_with_ai()` 提供简单函数式入口。
- CLI 的 `qcompiler compile` 支持 SABRE 和 AI 后端。
- CLI 的 `qcompiler eval` 输出 SABRE/AI 状态对比。

V14 修复了一个关键问题：早期展示路径实际仍调用 Qiskit SABRE 重编译，
不能证明 AI 路由器真的参与了 SWAP 决策。现在 `AIRouter` 会按 AI trace
构建电路，评测报告中的 AI 列来自真实 AI 路由路径，并用 `OK`、
`INCOMPLETE`、`N/A` 显示状态。

## 9. SABRE 对比与真实 P1 结果

老师任务要求与现有基准编译器比较。本项目使用 Qiskit SABRE 作为稳定
baseline，并通过 `scripts/eval_mqt_bench.py` 生成报告。最新 P1 结果如下：

- 运行时间：2026-05-04。
- 模型：`models/v14_tokyo20/checkpoint_ep25333.pt`。
- 拓扑：IBM Tokyo 20Q。
- 主集合：`qft`、`qaoa`、`ghz`、`vqe` × 5/10/20 qubits。
- SABRE 完成率：12/12。
- AI 完成率：4/12。
- AI 超越 SABRE：0/4 completed comparable rows。
- 完成且 SABRE SWAP > 0 的行上，AI/SABRE 平均比例为 2.500。

完整报告：

- Markdown: `models/v14_tokyo20/eval_report_mqt.md`
- JSON: `models/v14_tokyo20/eval_report_mqt.json`

这个结果不能被包装成“AI 已经打败 SABRE”。它说明当前 checkpoint 只适合作为
研究和诊断对象，而不是替代 SABRE 的生产路由器。项目的可信价值在于：能用
同一套脚本复现 baseline、AI 路径、完成率和失败点。

## 10. V14/V15 失败诊断与算法演进

V14 的主要工程修复包括：

- SABRE baseline 缓存，避免训练时重复运行昂贵 baseline。
- 阶段化 action mask，降低早期探索难度。
- 奖励分层，缓解从 5Q 到 10Q/20Q 的 reward cliff。
- pass manager 真集成，避免把 SABRE 输出误当 AI 输出。
- checkpoint 加载兼容，支持从 CUDA 训练 checkpoint 的 `model_state` 加载到 CPU。

P1 评测推翻了一个关键假设：`checkpoint_ep25333.pt` 不能作为可靠 warmstart
支持 V15 继续长训。云端 V15 在 iter326 停滞，进一步暴露 self-play 基本串行、
`num_workers` 没有真正接入训练循环、MCTS 叶节点推理未做 batch inference 等
架构瓶颈。

因此 V15 的定位是 bounded POC：保留 MCTS+GNN 路线，但必须先验证并行 self-play、
batch inference、吞吐和 completion，再谈长期训练。

## 13. 当前结论

本项目完成了课题四的主要工程闭环：

- 将量子路由问题建模为带物理拓扑约束的 MDP。
- 实现 DAG 前沿门执行、动作 mask、奖励函数和 GraphSAGE policy。
- 提供 Qiskit 兼容的 CLI/API/AIRouter 路径。
- 使用 SABRE 做稳定 baseline，并沉淀 MQT-Bench 对比数据。
- 通过真实评测发现 AI checkpoint 未达标，并定位 V15 后续架构问题。

当前 AI 未超过 SABRE，这是必须诚实展示的结果。项目的完成度体现在“问题
建模、代码实现、可复现评测、失败诊断、后续路线”这条闭环，而不是包装一个
未经数据支持的性能胜利。
