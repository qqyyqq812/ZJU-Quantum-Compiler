Quantum routing heuristic lab.

This project maps logical quantum circuits onto constrained hardware topologies such as IBM Tokyo 20Q. The current practical path compares Qiskit SabreSwap heuristics, whose installed implementation includes LightSABRE modifications, and uses lookahead as the default static recommendation.

Use it as a small tool first: choose a checked-in circuit or paste inline OpenQASM, select a heuristic, run the local API, and compare SWAP/depth results without claiming the experimental AI router is production-ready.

Local API and CLI

GitHub Pages runs the heuristic lab in static mode. The current local API now accepts a heuristic parameter for the stable SABRE backend, so you can compare basic, lookahead, and decay against the checked-in static table. The live path is intentionally fixed to trials=1 for stable static/live reproducibility.

1. Install

Install the package in editable mode with the existing virtual environment.

pip install -e .[dev]

2. Reproduce default route

Use the stable SABRE backend locally with the practical default heuristic.

qcompiler compile examples/qft5.qasm --topology tokyo --backend sabre --heuristic lookahead

3. Start API

Enable live mode for this page on your machine.

uvicorn src.server.app:app --reload --port 8765

Background evidence

AI-router history is kept as workload and failure-analysis evidence only. The practical website path stays centered on reproducible SABRE heuristic routing.

Roadmap

The next steps keep the tool useful first, then add richer algorithms only when they improve reproducible routing.

  • Keep live heuristic comparison as the main website workflow.
  • Add a documented multi-trial mode only after adding matching expected rows.
  • Improve custom OpenQASM input and result readability.
  • Keep bounded search as failure-analysis evidence, not a website algorithm.
  • Use V14/V15 AI history as background evidence, not a product claim.
  • Add MCTS or learning-based routes only after small experiments justify them.
